# vuln-lab

Учебный проект по управлению уязвимостями: разворачиваю уязвимые приложения, автоматизирую сканирование, разбираю находки и показываю, как их чинить на этапе проектирования (security by design).

## Что сделано

- [x] Развёрнут уязвимый стенд в Docker: OWASP Juice Shop и DVWA с базой данных.
- [x] Проведено пассивное сканирование обоих приложений (OWASP ZAP). *(Активное сканирование в локальном Docker под эмуляцией Apple Silicon не укладывалось по времени, поэтому его место — в CI на Linux-раннере. Это отражает реальную практику: тяжёлые DAST-сканы запускают в пайплайне, а не на локальной машине.)*
- [x] Написан кастомный парсер отчётов ZAP на Python: переводит сырой JSON в приоритизированную Markdown-сводку с уровнями риска.
- [x] Проведён ручной поиск уязвимостей через Burp Suite и составлен подробный баг-репорт (Open Redirect с обходом валидации).

## Ключевой вывод

Число находок автоматического сканера не равно реальной защищённости приложения. Пассивный скан DVWA не показал ни одной критичной уязвимости, хотя SQL-инъекции и XSS там есть: пассивное сканирование ловит «гигиену» (заголовки, куки), но не подтверждает эксплуатацию. Реальная уязвимость (Open Redirect с обходом существующей валидации) найдена только вручную. Автоматизация даёт зацепки, а подтверждает их и оценивает риск (Severity) человек.

## Артефакты

- `docker-compose.yml` — конфигурация стенда (изолированные сети, том для базы данных).
- `zap_parser.py` — парсер отчётов сканера ZAP.
- `reports/` — результаты сканирования и сгенерированные сводки находок.
- `bug-report.md` — детальный разбор уязвимости Open Redirect, найденной вручную.

## Запуск

```bash
docker compose up -d
```

- Juice Shop: http://localhost:3000
- DVWA: http://localhost:4280 (admin / password)

Приложения намеренно уязвимы и доступны только с локального компьютера (`127.0.0.1`).
